Pre-check-in — ID capture and field provenance

Customer information is prefilled from a photo of the driver's licence before the checkout session starts, so the counter is a confirmation, not a typing exercise. The photo is read by the OCR path RFM already ships. The design's whole weight is on the confirmation step: what the machine read, how sure it was, and what a human changed.

Design only — no application code touched. The extraction is backend/src/modules/kiosk/kiosk-id-ocr.extract.js (extractLicenseFront → { fields, confidence, notes }), served by idPhotoExtract() in kiosk-checkout.service.js, which is advisory by construction — it “stamps NOTHING”. This screen is where advisory becomes confirmed.

Terminal-side ID scanning is deliberately absent. Dejavoo's Scanner Reader SDK is an Android SDK for apps running on the terminal (ScannerActivity / startScan() / onSuccess(String)), not a REST operation RFM can trigger — and it returns an opaque string rather than parsed licence fields. Hector already demoted a pdf417 scanner in favour of photo + OCR after an iPad re-test. The cost of revisiting it is in NOTES §7.

The photo path is an accelerator laid over a complete manual flow; it is never a prerequisite.

Never show the customer a failure they cannot act on. OCR_UNAVAILABLE (503), EXTRACT_FAILED (502) and EXTRACT_LIMIT (429) are three different problems for an engineer and one problem for a renter: the photo route is closed, the form is open. The staff-side panel does distinguish them, because an agent hitting OCR_UNAVAILABLE needs to tell an admin to configure a key.
3 · Where provenance goes — pre-check-in is not the last place it matters

A badge that exists only on the form it was set on is decoration. Provenance is carried onto the checkout session's step 1, so the agent at the counter knows whether the name on the contract was read by a machine or confirmed by a person.

Pre-check-inset
Each field records how it got its value and who touched it last. A field the OCR filled and nobody looked at stays Scanned — the honest state, and the one worth surfacing later.
Checkout step 1read + confirm
The agent sees the badges and confirms against the physical licence. Confirming promotes Scanned to Confirmed with the agent's user id. Nothing goes on a signed contract still marked Scanned.
Audit trailforever
“The name on this agreement was OCR-read at 09:14 and confirmed by agent M. Ruiz at 14:21” is the sentence that settles a disputed rental. Telemetry stays counts-and-confidence only — never the extracted PII, exactly as recordSessionTelemetry does today.
