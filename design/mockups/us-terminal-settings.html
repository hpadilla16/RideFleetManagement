iPOSpays credentials

Enabled

Dejavoo issues three separate credential families and they are not interchangeable. Every one of them is write-only and encrypted at rest; the panel shows only whether a value is on file.

Which credential does what.
1 · HPP auth token — mints hosted payment links (fallback payments). Sent as the lowercase token header.
2 · API key + secret key — exchanged for a JWT; used for payment-status queries and the Transact card-not-present rail (the deposit hold).
3 · Terminal Auth key + TPN — drives the physical QD2. Configured in the section above.
A terminal checkout touches all three: the terminal for the sale, Transact for the deposit, HPP only if it falls back.

Agent decides per checkout Step 5 offers both: send the link, or do the walkthrough now. The agent picks based on the queue behind them. This is the setting ON state.
Always agent-led No choice screen. Straight to the walk-around on the agent's phone or this tablet. The setting OFF state — exactly today's flow.
One US-specific consequence. On the terminal path the renter has already signed the agreement in step 2, so the second signature at the end of an agent-led inspection is redundant. It should be raised only when the walkthrough finds new damage — in which case that single acknowledgement goes back to the QD2 rather than to a phone.
