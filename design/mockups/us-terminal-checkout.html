US Terminal Checkout — iPOSpays / SPIn

A checkout session dedicated to US tenants on a Dejavoo QD2. The contract is initialled and signed on the terminal, the sale tokenizes the card, and the security deposit is held against that same token with no second tap. Inspection stays where the tenant puts it.

Scope discipline: design only — no application code touched. Every element below cites the RFM code it maps onto so the build phase does not re-derive it. The four steps are Hector's, verbatim (2026-09-04): “Step 1 verify info, Step 2 initialling and signing contract on terminal, then payment with card on file and tokenization, then security deposit capture.” Rationale, the failure matrix, the L3 field mapping and the open questions for Dejavoo live in us-terminal-checkout-NOTES.md.

Composition order is fixed in spin-charge.service.js: the local/non-local rule first, then the debit uplift. Both only ever raise. The agent sees the arithmetic, not a number.

If this hold declines, the sale is voided. The existing rollback stands: a successful sale plus a failed deposit calls /v2/Payment/Void so nobody is charged for a rental whose deposit could not be secured, and the wizard reports rollbackPerformed: true. Do not let the US flow quietly skip the hold instead.

5 · Inspection stays configurable — agent-led or customer-led

Unchanged from today. GET /api/settings/customer-inspection returns { enabled, checkinModel }; when enabled is false, step 5 is the QR/handoff flow, and when true the agent chooses per checkout. The only US-specific change: the renter has already signed on the terminal, so the agent-led branch no longer needs step 6's second signature.
