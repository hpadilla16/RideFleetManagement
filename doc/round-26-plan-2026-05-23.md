## Tonight's hotfix cascade (for the record)

The SPIn AutoRental endpoint returned StatusCode 2201 / ResultCode 2 four different times tonight. Each `2201` masked a different validation issue. The journey:

1. **First 2201**: `Error: SPIn request failed (no body)` — `recordTxError` wasn't persisting `rawResponse`, so we had no diagnostic.
   - Fix `recordTxError` to save `err.spinResponse` (commit `df36331`-ish).
2. **Second 2201**: Wrapper field name. We sent `{ RentalData: {...} }` but SPIn requires `{ AutoRental: {...} }`.
   - Commit `cc4efdd` — `RentalData` → `AutoRental`.
3. **Third 2201** (became 500): Flat AutoRental object → SPIn parser crash with generic ASP.NET 500. Schema requires nested sub-objects.
   - Commit `02af640` — nested `AutoRentalAgreement` / `AutoRentalRenter` / `AutoRentalVehicle` / `AutoRentalPricing` / `AutoRentalPickup` / `AutoRentalReturn` / `AutoRentalDistance`.
4. **Fourth 2201** (back to 2201): `ExtraCharges[0]` invalid value AND `Cart.Amounts` missing AND `Cart.Items[].Price` required.
   - Commit `ddd6d4b` — `ExtraCharges: ['NoExtraCharge']`, `Cart.Amounts: [{Name, Value}]`, `Cart.Items[].Price`.
5. **The Sale request finally reached the terminal** — customer prompt appeared. End-to-end code path validated.

## Notes / lessons

- **iPOSpays/Dejavoo docs do not document StatusCode 2201.** Only 2001–2011 (proxy errors) and 2101–2102 (callback errors) are documented. 2201 appears to be a SPIn proxy validation error specific to AutoRental endpoints. The `DetailedMessage` field contains the actionable info — `recordTxError` capturing `rawResponse` was essential.
- **Cascading rebuilds were the slowest part of the night.** Each round-trip was: edit code → commit → push → droplet `git fetch --force` → `docker compose build --no-cache backend worker` → restart → retry → query rawResponse. That's 5–10 minutes per iteration. Investing in faster local feedback (real Dejavoo sandbox terminal + faster docker rebuild) would have saved hours.
- **`docker compose build --no-cache` is required when only one file changes.** The cached build mistakenly stayed on the old image even when the source file was updated, because Docker compared file mtimes incorrectly with bind-mounted source. `--no-cache` is the safe move.
- **Tag force-push works fine on the droplet** as long as you `git fetch --tags --force` (without `--force`, local tags don't update from the remote re-push).
- **Round 25's local smoke test passed but didn't catch the AutoRental schema mismatch** because our SPIN_MOCK didn't actually validate against the real SPIn schema. A more thorough mock that validates against the JSON schema would have caught this.
