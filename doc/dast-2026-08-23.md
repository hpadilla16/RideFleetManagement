# DAST — dynamic security scan + remediation (2026-08-23)

**Scope:** the RideFleetManagement backend API + web frontend, current `main`.
**Purpose:** due-diligence evidence for the TL International integration. Complements the
static analysis (gitleaks + Dependabot, see `doc/security-scanning-2026-08-22.md`) with a
*running-application* scan.
**Tool:** OWASP ZAP (`ghcr.io/zaproxy/zaproxy:stable`) — baseline (passive) + `zap-api-scan.py`
(active, OpenAPI-driven) and `zap-baseline.py` (frontend).

> **Method note (isolation):** every scan ran against a **fully local, throwaway** copy of the
> stack (disposable Postgres, alternate ports, its own compose project). **Production, the
> droplet, and Supabase were never touched.** The active/aggressive scanning that a shared
> production tenant could not safely absorb (a 1-vCPU box) was therefore possible without risk.

---

## 1. Headline result

- **No High / critical / exploitable findings.** No SQL injection, XSS, path traversal, command
  injection, SSRF, or authentication bypass across ~33k active requests over 568 API paths.
- **Multi-tenant isolation is solid — no cross-tenant data access (BOLA/IDOR).** With tenant A's
  ADMIN credentials, every attempt to read or mutate tenant B's objects (vehicles, customers,
  id-photos, password-reset, reservations) returned **404/403**; list endpoints returned only the
  caller's own tenant's rows. Forged/tampered JWTs and unauthenticated calls were rejected (401).
- All actionable findings were **Low–Medium** (headers / info-hygiene / input-validation
  robustness). **Every one was fixed and re-verified** (§3–§4).

## 2. Coverage

- **Two passes.** Pass 1: unauthenticated surface (the highest-value attack surface — public token
  routes, login, register, webhooks, public booking). Pass 2: **authenticated** active scan with a
  seeded tenant-scoped **ADMIN** (Bearer JWT + `X-Tenant-Token` injected on every request), plus a
  targeted cross-tenant (BOLA/IDOR) probe using two tenants.
- **Endpoint source of truth:** the served OpenAPI spec (`/api/docs/openapi.json`) — 568 paths /
  671 operations, 104 public.
- **Known gap:** the automated active scanner exercises data-mutation endpoints shallowly; the
  cross-tenant authorization checks (the crown-jewel risk here) were done as an explicit manual
  matrix, which passed.

## 3. Findings → remediation (all fixed, all re-verified against a running instance)

| # | Finding (severity) | Fix | Verified |
|---|---|---|---|
| 1 | Public payment pages (`/public/booking/.../payment-return`, `payment-cancel`) served HTML with no anti-clickjacking header (Med) | Per-page `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` | 200 + both headers |
| 2 | `X-Powered-By: Express` fingerprint leaked (Low) | `app.disable('x-powered-by')` | header absent |
| 3 | API responses missing `X-Content-Type-Options` / `Referrer-Policy` / `Permissions-Policy` (Low) | Global response-header middleware (safe for JSON **and** HTML — restricts neither framing nor resources, so the WebView payment bridge / processor hosted-fields pages are unaffected) | present on every response |
| 4 | Malformed input (bad id / junk query) surfaced as opaque **500** on several endpoints (Low) | Global error handler maps Prisma `P2023/P2009/P2000` + `PrismaClientValidationError` → **400** (generic message — a raw Prisma message names columns/types = schema leak) and `P2025` → **404** | junk → 400 `Invalid request` |
| 5 | Loaner `statement-print` HTML page had no anti-clickjacking header (Med) | same per-page treatment as #1 | 200 + both headers |
| 6 | `reports-v2` PDF 500 path echoed `err.message` → leaked the puppeteer/Chrome executable path + version (Med, info-disclosure) | 500 path returns generic `Internal error`; only the typed 4xx keeps its message | 500 body = `{"error":"Internal error"}` |
| 7 | `citations` local error handler echoed raw `err.message`, bypassing the global sanitizer — a null byte leaked a raw Prisma ConnectorError (Med, info-disclosure) | `handle()` maps Prisma client errors to a generic 400 and never echoes their message | `?status=%00junk` → generic, no Prisma text |
| 8 | `Reservation not found` thrown untyped → **500** on `card-on-file` and siblings (Low) | the 3 throws now carry `status: 404` | bogus id → 404 |
| 9 | Input-validation errors surfaced as **500** on `vehicle-classes` (junk `limit`), `settings/market-pricing-config`, etc. (Low) | **root-cause:** (a) the global handler now honors the `err.httpStatus = 400` convention used by 19 service files, which it had silently dropped to 500; (b) the shared validators in `lib/request-validation.js` now throw with `status: 400`, so every endpoint using them returns 400 | junk `limit` → 400; bad config body → 400 |

**Explicitly dismissed as false-positive / benign** (with reasoning, not silently): "Application/Debug
Error Disclosure" (the 500 bodies are the sanitized `{"error":"Internal server error"}`, no stack);
timestamp disclosure / suspicious comments / private IP / "dangerous JS functions" (Next.js
dev-bundle artifacts and JSON timestamps); missing COOP/COEP/CORP (omitted deliberately — COEP/CORP
can break cross-origin resource loads for no real gain here); CSP on `payarc-bridge` (that page
embeds the processor's hosted-fields **by design**).

## 4. Verification

Every fix above was re-checked with `curl` against a fresh local instance seeded with two
tenant-scoped ADMINs: all 9 PASS, no regressions. Unit coverage added/updated:
`src/lib/error-status-passthrough.test.mjs` now pins the extended contract (typed 4xx +
`httpStatus` + Prisma client-input → generic 4xx, all *before* Sentry). Files changed:
`main.js`, `lib/request-validation.js`, `modules/public-booking/public-booking.routes.js`,
`modules/dealership-loaner/dealership-loaner.routes.js`, `modules/reports/reports-v2.routes.js`,
`modules/citations/citations.routes.js`, `modules/rental-agreements/rental-agreements.service.js`.

## 5. Residual / follow-up (non-blocking)

- Re-validate the frontend CSP against a **production** build (the dev-mode `unsafe-inline` ZAP
  flagged is a Next.js dev artifact, not the shipped policy).
- The `httpStatus`/`status` typed-error conventions now both work; consolidating on one is a future
  tidy-up, not a security item.
- Optional: a follow-up authenticated active scan focused on data-mutation endpoints (this run's
  automated authenticated coverage of those was shallow; the manual cross-tenant matrix passed).

**Bottom line for the DD:** a running-application scan found **no exploitable issues**, and
confirmed **tenant isolation holds**. The only findings were header/info-hygiene and
input-validation robustness — all remediated and re-verified. No High/critical remains.
