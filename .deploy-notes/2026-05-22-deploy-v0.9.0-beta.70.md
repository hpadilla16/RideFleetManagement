## Deploy commands (on droplet)

```bash
ssh root@ridefleetmanager.com
cd ~/RideFleetManagement

# 1. Pull the new tag
git fetch --tags
git checkout v0.9.0-beta.70
git log --oneline -5

# 2. Rebuild + restart the prod stack
docker compose -f docker-compose.prod.yml up -d --build --force-recreate
docker compose -f docker-compose.prod.yml ps

# 3. Wait ~30s for healthy. Verify:
curl -fsS http://localhost:4000/health
docker logs fleet-backend-prod --tail 30
docker logs fleet-worker-prod --tail 30
docker logs fleet-frontend-prod --tail 10

# - /health returns ok: true
# - No errors in backend/worker logs
# - Frontend ready
```

## What to watch in logs

```bash
ssh root@ridefleetmanager.com
docker logs fleet-backend-prod -f | grep -E "counter-orchestrator|spin|Sale|Auth|SignatureData"
```

Key things to see:
- `[counter-orchestrator] starting` (flow initiated)
- `[counter-orchestrator] rental fee charged at pickup ... hasSignature: true`
- `[counter-orchestrator] persisted signing fields ... signatureCaptured: true`
- `[counter-orchestrator] completed` (success)

Things to NOT see:
- `404` from `api.spinpos.net` (means the Sale-driven flow is still trying
  to hit a removed endpoint — should be impossible after round 25)
- Prisma errors about `settingsJson` (means schema isn't in sync)
- `Module not found` errors (means npm install in container failed)
